1. 리엑트의 탄생
    탄생 배경
    - React는 페이스북 개발팀이 화면 업데이트를 위해 개발하던 중 탄생
    - React 자바스크림트 기반의 '라이브러리'
    - 2013년도 등장한 선언형 방식으로 UI를 표현 함
    - 현재는 리엑트.19을 API 지원 : 항상 최신버전으로 개발 권장

    왜 새로운 기술이 필요했나?
    - 기존의 기술 한계점: 정적인 웹 구축에 초점, 대규모 앱 구축에 부적합
    - 페이스북의 요청 : 
        다양한 인터렉션(사용자와의 양방향 소통)
        변화가 잦은 대규모 앱 필요

    목적
    변화가 자주 일어나는 대규모 애플리케이션에 적합한 
    쉽고 효율적인 라이브러리를 만들자

2. 리엑트의 특징 3가지
    컴포넌트 기반
        - UI를 독립적이고 재사용 가능한 컴포넌트 단위로 분리
    가상돔(Vitual DOM)
        - 실제 DOM을 복제하여 가상돔에서 필요한 부분만 업데이트 진행한 후
          한번에 실제 DOM에 반영하여 빠른 업데이트를 진행
    단방향 데이터 흐름
        부모 컴포넌트 > 자식 컴포넌트로 데이터를 전달함 (🅾️)
        자식 컴포넌트 > 부모 컴포넌트로 데이터를 전달 불가 (❌)

3. 리엑트 앱 생성
    vite(비트) - 리엑트 라이브러리를 제공하는 오픈 API
    기존 CRA를 대체하는 라이브러리
    Vite를 활용한 리엑트 앱 생성
        개발 환경 구성 - Node.js 설치 및 확인
            node -v, npm -v
        리엑트 앱 생성 : my-app
        형식: npm create vite@latest [앱이름(프로젝트명)]
        npm create vite@latest 

4. 리엑트 앱 동작 순서
    npm run dev 서버 실행 : http://localhost:5173/index.html
    index.html 렌더링
    main.jsx 호출 
        index.html의 root 아이디에 import한 컴포넌트 추가
    App 컴포넌트 렌더링 : virtual dom

5. 컴포넌트
    정의
    - UI를 구성하는 독립적이고 재사용 가능한 단위
    - 함수가 HTML을 반환하는 구조 : return()
    - 레고 블록을 조합하여 페이지를 구성
    종류
    - 함수형 컴포넌트 : 2018년 이후 사용됨, 현재 표준
        function [컴포넌트명] () {
            return;
        }
    - 클래스 컴포넌트 : 거의 사용 안함
        class [클래스명] extends React.Componet {
            render()
        }
    특징
    - 재사용성: 한 번 생성 여러번 사용
    - 독립성: 각각의 컴포넌트를 독립적으로 생성하여 유지보수 향상
    - 조합 가능: 컴포넌트를 조합하여 화면을 구성
    구성요소
        형식 :
        function [컴포넌트명]( Props ) {
            // 로직, 컴포넌트 상태 관리

            let name = "홍길동"

            return (
                <h1>{name}</h1>
            )

        }
        const [컴포넌트명] = ( Props ) => {
            // 로직, 컴포넌트 상태 관리
            return ()
        }
        - 컴포넌트명은 첫글자 대문자
        - 컴포넌트 인자값은 Props로 전송되며, 단방향으로 진행
        - 로직 상태관리 등
        - return 함수를 통해 화면 렌더링(출력)
        - return 함수는 JSX 문법이 적용됨
    
        부모 컴포넌트 VS 자식 컴포넌트
        - 부모 컴포넌트 : index.html에 실제 렌더링되는 컴포넌트
        - 자식 컴포넌트 : 부모 컴포넌트의 return 함수에서 호출되는 컴포넌트

        Export / Import
        - 컴포넌트 앞에 export를 추가함
        export (default) function [컴포넌트명]() {
            return ()
        }

        - 별칭을 이용하여 자식 콤포넌트를 import 함
        - export default 컴포넌트 컴포넌트명 그대로 사용
        import [별칭] from '컴포넌트 위치.확장자'
